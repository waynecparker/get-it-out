# Get It Out — Data-flow inventory

Prepared 2026-10-09 from the code on branch `checkpoint-6` (commit
`233333b` and later). This describes what the app **actually does**, for
the Privacy Policy, Google Play Data safety, Apple privacy labels and legal
review. Anything marked **[verify]** depends on a vendor's own terms or
account settings and must be confirmed from the source before it's
published. Not legal advice.

## 1. Summary

| Data | Where it goes | Stored? |
|---|---|---|
| Email + password | Supabase Auth | Yes, until account deletion |
| Voice recording | Supabase function → **OpenAI** (transcription) | Only if the user's setting is "Save audio and transcript" |
| Transcript, typed messages, conversation history | Supabase function → **Anthropic** (reply) | Only if the user saves the conversation, and not under "Delete everything after each session" |
| AI replies | Generated by Anthropic | Same as transcripts |
| Safety-panel flag | Saved message row only | Only on saved conversations |
| Storage preference, 18+ confirmation | Supabase | Yes, until account deletion |
| Subscription status, founder number | RevenueCat → Supabase | Yes, until account deletion |
| Purchase / transaction records | Google Play / Apple → RevenueCat | Held by RevenueCat and the store **[verify retention]** |
| Usage counts (audio seconds, AI tokens, timestamps — no content) | Supabase | Yes, until account deletion |
| Biometric unlock (app lock) | Phone only (OS biometric API) | Nothing leaves the device |

No analytics, advertising, crash-reporting or tracking SDKs are installed.
The app never sends the user's email or name to RevenueCat.

## 3. Step-by-step flows

### Sign-up / sign-in
1. Email + password go to **Supabase Auth** (password stored hashed by
   Supabase). The 18+ checkbox travels as sign-up metadata and is saved to
   `profiles.age_confirmed`.
2. The session token is stored on the phone in the OS secure keystore
   (`expo-secure-store`).
3. Supabase platform logs record requests, including IP addresses, for
   their log-retention period **[verify retention on our plan]**.

### Recording → transcript
1. Audio is recorded on the phone (AAC/M4A, mono, 16 kHz) into the app's
   temporary cache folder.
2. The audio is sent to our `transcribe` function, which forwards it to
   **OpenAI Whisper** (`whisper-1`) and returns the text. Our function does
   not store the audio or the text. The audio length (seconds) is recorded
   in `usage_events` for cost and fair use.
3. **This happens in every storage mode**, because transcription needs it.
   OpenAI's handling of API inputs (retention, abuse monitoring, training)
   is governed by their API terms **[verify current OpenAI API data
   retention and confirm training is off for our organisation]**.

### Reply
1. The confirmed transcript **plus the conversation so far** (earlier
   transcripts and replies in the same session) is sent to our
   `ai-response` function, which sends it to **Anthropic Claude** with the
   system prompt.
2. The reply and a safety classification (none / concerning / immediate)
   come back. Our function stores nothing except a usage count (token
   numbers, timestamp) in `usage_events`. The safety classification is not
   logged anywhere unless the user saves the conversation (then only as a
   `triggered_safety_panel` true/false flag on that message).
3. Anthropic's handling of API inputs is governed by their commercial
   terms **[verify current Anthropic API retention and no-training
   terms]**.

### Saving (depends on the user's storage setting)

| Setting | Transcript + replies | Audio |
|---|---|---|
| Save audio and transcript (default) | Saved to Supabase | Uploaded to private Supabase Storage (`{user_id}/{message_id}.m4a`), local copy deleted |
| Transcript only | Saved to Supabase | Never uploaded; local copy deleted |
| Delete everything after each session | Nothing saved | Never uploaded; local copy deleted |

- A conversation the user discards is never saved, in any mode.
- In every mode, the audio and transcript still pass through OpenAI and
  Anthropic during the session (see above).
- Saved audio plays back via signed URLs that expire after 1 hour.
- Abandoned temporary recordings (e.g. app killed mid-recording) are
  deleted the next time the app starts.

### Subscriptions
1. The app logs RevenueCat in with the **Supabase user id** (a random
   UUID — not the email).
2. Purchases go through **Google Play / Apple**; RevenueCat validates them.
   We never see card details.
3. RevenueCat sends events (trial, renewal, cancellation, expiry) to our
   `revenuecat-webhook`, which stores subscription status, product, period
   dates, store, environment, and founder number in `subscriptions`, plus
   the event id/type/time in `revenuecat_events`.
4. RevenueCat's own SDK collects purchase and device/app information
   **[verify against RevenueCat's Data safety / privacy-label guidance]**.

### Fair-use metering
`usage_events` holds per-call counts only: kind (transcription / AI reply),
audio seconds, input/output tokens, timestamp. Used for cost tracking and
abuse limits. Never contains content.

### Server logs
Our functions log errors (e.g. a provider failure status), the user id
when a fair-use limit is hit, and webhook event ids/types. They never log
transcripts, replies or audio. Logs are kept for the Supabase plan's log
retention **[verify]**.

## 4. Deletion — what each control actually removes

| Control | Removes | Doesn't remove |
|---|---|---|
| Delete one conversation (5-second undo) | Its messages, replies, safety flags, and saved audio files | Usage counts; anything already processed by OpenAI/Anthropic |
| Delete all history | Every conversation, message and saved audio file | Same as above |
| Delete account | The auth account and every database row (profile, preferences, conversations, messages, audio records, subscription, usage events, founder holds) via cascade, plus all saved audio files; the RevenueCat customer **only if `REVENUECAT_SECRET_API_KEY` is set — it isn't yet** | The store subscription itself (the app tells the user to cancel it in Google Play / App Store); webhook event log rows are kept with the user link removed; provider-side copies; Supabase backups **[verify backup retention]** |

Founder numbers are never reissued after an account is deleted (by
design), but the deleted user's subscription row, including their number,
is removed.

**Gaps to close before launch**
- Set `REVENUECAT_SECRET_API_KEY` so account deletion also deletes the
  RevenueCat customer.
- Google Play requires a **web page** where users can request account
  deletion without the app — not built yet (needs a domain).
- Data export ("Export my data") isn't built — access requests would be
  handled by email until then.

## 5. Third parties (processors)

| Provider | Role | Data |
|---|---|---|
| Supabase (Tokyo) | Database, auth, file storage, server functions | Everything stored |
| OpenAI | Speech-to-text | Audio, per recording |
| Anthropic | AI replies + safety classification | Transcripts and conversation history, per turn |
| RevenueCat | Subscription management | Supabase user id, purchases, device/app info |
| Google Play / Apple | App distribution, payments | Store account, payment details (we never see them) |
| Expo (EAS) | Builds the app | Source code and build config only — no user data at runtime |
